# 접시 건조 센서 앱 · 간단 명세 v0.3.0

LG AX · 키친에서 치킨먹기

작성: 황대겸

## 하려는 것

건조대 옆에 온습도·빛 센서를 붙이고, Android에서 주변 수치를 확인하고 저장한다. 건조 지수는 일단 임의 계산으로 표시한다. 실제 접시 물기와의 관계는 아직 모른다.

## 구성

- 일반 ESP32 DevKit + DHT22 + LDR + 10kΩ 저항
- ESP32가 만드는 개발용 Wi-Fi에 휴대폰 연결
- Java로 만든 Android 한 화면
- 앱 내부 CSV에 기록 후 시스템 파일 선택기로 내보내기

Android 8.0 이상을 기준으로 한다. ESP32-C3 등 다른 보드는 핀 배치를 따로 바꿔야 한다.

## 화면과 버튼

| 항목 | 현재 동작 |
| --- | --- |
| ESP32 주소 입력 | 전체 측정 URL을 입력. 빈칸이면 휴대폰 센서만 사용 |
| 측정 시작 | 휴대폰 센서 등록, 외부 주소가 있으면 HTTP 요청 시작 |
| 측정 중지 | 센서 등록과 반복 요청을 중지하고 표시값을 미측정으로 변경 |
| 연결 상태 | 짧은 상태 배지와 연결 중·마지막 수신 시각·실패 원인·자동 재연결 안내 표시 |
| 외부 센서 수치 | 주변 온도 °C, 습도 %, 빛 ADC 0~4095 |
| 휴대폰 센서 수치 | 조도 lx, 중력 크기 차이로 계산한 움직임 m/s² |
| 건조 지수 | 외부 센서 값으로 계산한 임시 점수 0~100 |
| 현재 값 기록 | 버튼을 누른 시점의 유효한 값 한 줄을 앱 내부 CSV에 추가 |
| CSV 내보내기 | 기록이 있으면 시스템 파일 선택기를 열어 저장 |
| 기록 요약 | 앱 내부 CSV의 기록 개수와 최근 기록 시각 표시 |

측정 중에는 주소 입력을 잠근다. 파일 선택기를 포함해 앱 화면을 벗어나면 측정을 중지한다. 돌아오면 다시 시작 버튼을 눌러야 한다.

화면은 지수 → 연결 → 외부 센서 → 휴대폰 센서 → 기록 순서다. 따뜻한 회색 바탕과 흰색 카드, 붉은 캡슐 버튼을 사용한다. 접시·물방울 자체 심볼을 적응형 앱 아이콘과 상단에 적용했다. 센서값은 각각의 칸으로 구분하고 주소 입력 레이블과 예시 URL을 항상 보여 준다. [디자인 기준과 파일별 책임](DESIGN_NOTES.md)에 출처와 Android 적용 내용을 적었다.

## 센서 연결과 통신

| 항목 | 값 |
| --- | --- |
| DHT22 DATA | GPIO4, 3.3V 쪽 10kΩ 풀업 |
| LDR | 3.3V → LDR → GPIO34 → 10kΩ → GND |
| 센서 측정 간격 | 3초 |
| Wi-Fi 이름 | `DishDrySensor-ESP32` |
| 개발용 Wi-Fi 비밀번호 | `dishdry123` |
| 기본 측정 주소 | `http://192.168.4.1/readings` |
| 요청 | `GET /readings` |
| 앱 요청 간격 | 5초 |
| 연결 / 읽기 제한 시간 | 각각 2.5초 |
| 앱이 읽는 응답 크기 제한 | 16 KiB |

정상 응답은 HTTP 200과 JSON이다.

| JSON 필드 | 의미 / 앱 검사 범위 |
| --- | --- |
| `device` | `dishdry-esp32` |
| `temperature_c` | 주변 온도, -40~80 |
| `humidity_percent` | 주변 습도, 0~100 |
| `light_adc` | 보정 전 빛 원시값, 0~4095 |
| `sample_age_ms` | ESP32가 측정한 뒤 경과 시간, 0~10000 ms |

DHT22 읽기에 실패하거나 측정값이 오래되면 펌웨어는 HTTP 503과 `sensor_unavailable` 오류를 반환한다. 없는 경로는 HTTP 404다. 앱은 응답이 잘못되거나 요청이 실패하면 외부 값을 비우고 연결 실패를 표시한다.

시간 초과는 Wi-Fi와 전원, 연결 불가는 Wi-Fi와 주소, HTTP 404는 `/readings` 경로, HTTP 503은 센서 배선과 전원을 확인하도록 안내한다. 그 밖의 HTTP 오류는 상태 코드를 함께 표시하고, 잘못된 측정 응답과 16 KiB 초과 응답도 구분한다. 내부 예외 메시지는 화면에 표시하지 않는다.

실패하면 다음 측정 주기에 자동으로 다시 연결한다는 문구를 표시한다. 다음 요청이 시작되면 `ESP32 다시 연결 중…`으로 바뀌고 이전 실패 원인을 함께 보여 준다. 요청 간격은 5초이며 같은 측정 세션에서 진행 중인 요청이 있으면 새 요청을 만들지 않는다. 측정을 중지하거나 화면을 벗어나면 반복 요청과 재시도 안내를 중지한다.

`sample_age_ms`와 앱이 수신한 뒤 경과 시간을 합쳐 10초를 넘긴 외부 값은 지수와 기록에 사용하지 않는다. 휴대폰 움직임은 마지막 이벤트 뒤 2초까지 유효하다. 휴대폰에 없는 센서는 `센서 없음`으로 표시한다.

## 임시 지수

```text
(100 - 습도) × 0.8 + (온도 - 15) × 1.5 + (빛 ADC / 4095) × 10
반올림한 뒤 0~100 범위로 제한
```

휴대폰 조도와 움직임은 지수에 넣지 않는다. 빛 ADC는 lux가 아니며, 지수는 접시 표면 수분을 측정하지 않는다. 보정과 건조 완료 판단은 이후 확인할 일이다.

## 기록 형식

앱 내부 파일 이름은 `readings.csv`, 내보내기 기본 이름은 `dish-dry-readings.csv`다. 자동 기록은 없고 기록 버튼을 누른 시점에만 추가한다.

| CSV 열 | 내용 |
| --- | --- |
| `recorded_at_utc` | 기록 버튼을 누른 UTC 시각 |
| `temperature_c` | 유효한 외부 온도 |
| `humidity_percent` | 유효한 외부 습도 |
| `light_adc` | 유효한 외부 빛 ADC |
| `phone_lux` | 휴대폰 조도 |
| `phone_motion_m_s2` | 최근 휴대폰 움직임 |
| `drying_index` | 유효한 외부 값으로 계산한 지수 |

측정하지 못한 항목은 빈칸이다. 유효한 값이 하나도 없으면 기록하지 않는다. CSV를 내보내도 앱 내부 원본은 유지한다.

CSV 요약 읽기, 기록 추가와 내보내기는 별도 파일 스레드에서 처리한다. 파일 작업 중에는 기록·내보내기 버튼을 비활성화한다. 파일 선택기를 취소하면 안내를 표시하고 내부 기록을 유지한다. 요약은 파일 길이가 바뀌었을 때만 다시 읽는다. 불완전한 행이나 잘못된 기록 시각은 요약 개수에서 제외하며 원본 파일은 보존한다.

## 아직 확인할 것

실물 배선과 휴대폰·ESP32 연결은 기기에서 확인이 필요하다. CSV 실제 파일 저장과 취소는 에뮬레이터에서 확인했다. 접시 재질·환기·센서 위치별 건조 지수는 검증 전이다. README의 구성 그림·시나리오와 와이어프레임은 개념 설명용이고, 앱 실행 화면은 원본 캡처다.
